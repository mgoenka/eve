Q&A primer

Q: How is this not Yelp + Hootsuite?

Both are 15 years old, neither is multimodal, neither generates content, neither plans whole evenings. Eve is the AI-native rebuild of both with the marketplace flywheel between them.

Q: How do you bootstrap diners without restaurant supply?

Day-one queries don't need supply — Eve plans grounded in Gemini's Bay Area knowledge. Eve Original badge is the upgrade once supply is there. Restaurants get a free trial; the content packs are the carrot.

Q: What about Toast?

Toast is POS that bolted on marketing. Templates, nobody uses them. Eve is marketing-first. Integrates with Toast/Square/Resy as data sources, doesn't compete on POS.

Q: How do you handle hallucinated restaurants?

Skeleton generation grounded with Gemini's Google Search tool. Eve Originals (verified, restaurant-published) get badge priority. v1.1 wires in Google Places API for ground-truth.

Q: Why solo? Will you raise?

Yes. 12 AI apps shipped this year. 120+ patents. I know how to ship and scale. Series Seed for a brand designer, an SF restaurant partnerships lead, an iOS engineer.

Q: Defensibility?

Vertical prompt corpus tuned by a vegetarian foodie founder; restaurant brand memory creates lock-in; the marketplace flywheel grows the index with every special. Horizontal AI tools don't compound any of these.

Technical Q&A — likely judge questions

Q: Show me where you use Gemini's interleaved output.

Three places. (1) /api/plan-experience/stop-image — TEXT+IMAGE in one call per venue. (2) /api/content-pack — hero food image + 3 Reel scenes interleaved with voiceover lines. (3) /api/eve-avatar — Eve's portrait. All on gemini-2.5-flash-image with responseModalities: ['TEXT','IMAGE'].

Q: How does barge-in work?

Web Speech API streams interim transcripts. On onresult, if eveSpeakingRef.current is true and ≥3 new chars, we call audio.pause(). speakAsEveAndWait resolves on pause as well as ended — that was the key fix. Also set walkingCancelRef = true so the walkthrough for-loop breaks. ~200 ms from first chars to silence.

Q: How do you avoid hallucinated restaurants?

Every venue lookup uses Gemini Flash with tools: [{ googleSearch: {} }]. The skeleton returns groundedSources[] URLs as proof. safeParseJson uses 3 strategies (direct, markdown-fence strip, last-balanced-brace scan) because Search-grounded responses sometimes prepend prose.

Q: ADK or ADK-pattern?

Pattern. agent.ts defines AgentRuntime, Tool, Agent in TypeScript that mirror ADK's API. Three tools registered: placesSearch, sceneCard, voiceLine. Exposed at /api/agent/run. ADK's official SDK is Python-first; we're TypeScript end-to-end. Native ADK swap is a 1-day post-hackathon move.

Q: How does the system handle errors?

Per-stop fault tolerance — 3 image calls are Promise.all, each in its own try/catch. A failing stop renders an apology card; other two still show. TTS falls back to en-US-Standard-C on synth error. JSON parsing is multi-strategy. Geolocation has a 7s timeout with a graceful "Eve asks where you are" fallback.

Q: What's your latency budget?

<15s on a warm Cloud Run instance. ~700ms parse-intent + ~3s grounded skeleton + ~8-10s parallel image generation + ~1s auto-walk handoff. Eve fills the wait with vibe-tinted filler talk so perceived latency feels <8s.

Q: Where does state live? How do you scale?

Cloud Run gen2 (2 CPU / 1 GiB), in-memory dining index for the marketplace demo, localStorage for restaurant brand. To scale: Firestore for the index (half a day), Memorystore for skeleton-cache de-dup on vibe+city, CDN for the avatar. Cloud Run autoscales horizontally.

Q: Why Web Speech API instead of Gemini Live?

Speed of build. Live API needs WebSocket plumbing. Web Speech API runs in the browser, free, cross-platform on Chrome/Edge/Safari. Trade-off is the 1.6s silence threshold. Live API migration is on the roadmap — would cut parse-intent latency ~60%.

Q: How do you avoid stale closures in the silence watcher?

Refs, not state. voiceListeningRef, voiceTranscriptRef, conversationActiveRef, userMutedRef, eveSpeakingRef, phaseRef are useRef mirrors of state, kept in sync via dedicated useEffects. The setInterval reads only the refs.

Q: How do you make the AI voice feel sensual, not robotic?

Voice: en-US-Neural2-F over Studio-O because Neural2 supports SSML and Studio felt flat. Wrapper: <prosody pitch="-2st" volume="soft"> + programmatic breath pauses (180ms after periods, 220ms after ellipses, 140ms after em-dashes). speakingRate: 0.98. Persona is also baked into the prompts — explicit "never say absolutely / leave it with me / vary endings" rules.

Q: Cost per plan?

~$0.04 per plan (1 Flash intent + 1 Flash+Search skeleton + 3 Flash Image + 2 Flash text + 5 TTS). Diner $4.99/mo × 30 plans = $1.20 cost vs $4.99 revenue. Restaurant $99/mo for daily content pack = ~$1.80 cost vs $99 revenue. 70%+ gross margins on both sides.

Q: Prompt-injection story?

User input lands in 3 prompts (eve-parse-intent, eve-refine, plan-skeleton freeText). None have privileged tool access. Worst case: weird venue names that still get Search-verified. No DB, no PII, no auth tokens. v1.1 adds a safety classifier pre-parse.

If something fails live

  • Mic doesn't catch: use the text box. Same plan, just slower.
  • Image doesn't render: keep narrating the next stop. Eve will catch up.
  • Voice doesn't play: point at the transcript bubble. The text is on screen.
  • Whole demo fails: open architecture page. Walk through SVG flow + endpoints. Same 5 minutes.
