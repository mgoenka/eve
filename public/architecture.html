01 / DIAGRAM

Top-down request flow

Every user-facing interaction maps to one of four primary flows: voice-driven plan synthesis, multimodal venue rendering, restaurant content pack generation, or marketplace publish. Each flow is a deterministic sequence of tool calls executed inside the Cloud Run service against Gemini and adjacent Google APIs.

03 / API SURFACE

HTTP endpoints

All endpoints are live on the same Cloud Run service. Architecture metadata is publicly readable at /api/health.

GET/api/health
Returns SDK version, models in use, registered tools, agent pattern declaration.
POST/api/agent/run
ADK-pattern agent runtime. Body: {plan: [{tool, input}]}. Returns tool outputs + per-call latency.
POST/api/eve-parse-intent
Parses spoken transcript to evening fields. Returns extracted slots + Eve's one-line spoken reply.
POST/api/eve-intro
Returns 4-phrase progress narration (streamed sequentially as Eve "thinks aloud").
POST/api/plan-experience/skeleton
Search-grounded 3-stop plan. Verifies real venues against the live web. No hallucinations.
POST/api/plan-experience/stop-image
Researches real venue details (Search), then renders interleaved text+image card.
POST/api/eve-story
7-beat second-person evening narrative with mood-arc + weather cue.
POST/api/eve-refine
Conversational re-plan from a follow-up message. Regenerates affected stops in parallel.
POST/api/suggest-special
Mines real reviews + current trends to suggest tonight's featured dish, plus competitor restaurants.
POST/api/content-pack
Generates IG post + 3-scene Reel + menu card + email + SMS in a single call.
POST/api/eve-avatar
Generates Eve's painterly portrait via interleaved Gemini image gen.
POST/api/tts
Cloud Text-to-Speech Studio-O passthrough (slowed, pitched). Reel mode falls through to Chirp 3 HD Aoede. Returns base64 MP3.

04 / CONVERSATIONAL LOOP

How the diner-side voice mode works

  1. User clicks Tell Eve. The Web Speech API starts streaming partial transcripts to the browser.
  2. onresult fires on every partial. lastSpeechAt is tracked on a useRef (state would be stale inside the silence interval).
  3. If 2.5s elapse with no new partial AND the transcript is non-empty, the recognizer stops and the transcript is POSTed to /api/eve-parse-intent.
  4. Server-side, Gemini Flash extracts {location, vibe, party, dietary, budget, cuisine, freeText}, decides whether to plan or to ask, and writes a one-line spoken reply.
  5. Reply is synthesized via Cloud TTS Studio-O voice, played through the <audio> element. Audio context was unlocked on the user's first pointerdown, so play() succeeds.
  6. If isComplete → execute the plan in parallel (3 stop-image calls + 1 narration + 1 outro). Otherwise the mic re-opens for the user's follow-up. Conversation loops.
  7. The user can interrupt Eve mid-speech. onresult with fresh transcript pauses Eve's audio, captures the user's input, and continues the loop.

05 / AGENT RUNTIME

ADK-pattern Agent / Tool / Runner

A native TypeScript abstraction in agent.ts mirrors Google's ADK architecture without taking on a fragile mid-hackathon dependency. Tools are typed function declarations; the runner executes them in a deterministic plan and reports per-call latency telemetry.

// Try the agent runtime live:
curl -X POST https://eve.mohitgoenka.com/api/agent/run \
  -H 'Content-Type: application/json' \
  -d '{"plan":[{"tool":"placesSearch","input":{"name":"Cucina Venti","city":"Mountain View, CA"}}]}'

// Returns:
{
  "agent": "EveBrain",

  "output": [{ "tool": "placesSearch", "output": { "details": "..." }}]
